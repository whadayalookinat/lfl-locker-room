# Locker Room v0.2 — implementation plan

Status: proposed architecture; not yet connected to a backend.

## Goals
- Keep the public GitHub Pages site free and separate from the existing LFL reporting repositories.
- Display a login landing page; only authenticated participants can read or post comments.
- Commissioner creates usernames and assigns initial passwords; no public sign-up.
- No participant-facing password change or recovery features. Commissioner manages resets.
- Persistent comments organized by NFL season and week.
- Commissioner can remove inappropriate comments and disable accounts.
- Display a reminder not to post personal, financial, or other sensitive information.

## Proposed architecture
- Frontend: static HTML, CSS and JavaScript on GitHub Pages.
- Backend: evaluate Supabase free tier for authentication and Postgres storage.
- Identity: use managed password hashing and sessions; never store plaintext passwords in the repository or browser code.
- Authorization: enforce access on the backend, not just through hidden frontend controls.
- Administration: commissioner-only operations using secure backend privileges; never expose a service-role key in GitHub Pages.
- Login-only reads: row-level security policies must require authentication for comment reads and writes.
- Usernames: consider a username-to-internal-auth-identity mapping; no requirement for participants to use personal email addresses.
- Password reset: administrator-controlled, with temporary credential distribution out of band.

## Initial data model (draft)
- league_members: member id, unique username, display name, active flag, role, auth identity id.
- comments: id, author member id, season, week, text, created at, removed at.
- Access policies: active members read; active members post as themselves; commissioner moderates.

## Safety and scope
- Fictional demo comments stay in the v0.1 baseline until real authentication and database policies are tested.
- Never publish real usernames, passwords, private keys or participant data in the repository.
- Limit message length and escape all user content.
- No payment features, public registration, profile customization, notifications, or password-change UI in v0.2.

## Build order
1. Confirm free backend account and project setup with the commissioner.
2. Create schema and row-level security rules.
3. Configure administrator-created accounts and login.
4. Replace in-memory demo posting with authenticated persistent comments.
5. Add commissioner moderation and account deactivation.
6. Smoke-test authorization and publish.

## Minimum validation
- Unauthenticated visitors cannot retrieve comments via API.
- Member A cannot post as Member B.
- Inactive accounts cannot read or post.
- Commissioner can remove a comment.
- Comment text is rendered as text, not HTML.
- Reload retains persisted comments.
- No secrets in source or deployed website.
